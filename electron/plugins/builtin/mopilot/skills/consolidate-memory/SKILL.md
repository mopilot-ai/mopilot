# Consolidate memory

Memory should be short, true and easy to find. Consolidating means merging duplicates, removing what is stale or wrong, and keeping an index small.

## 1. Find this harness's memory

- **Claude Code.** The auto-memory folder for this project. Your system prompt names it (a `memory` folder under the account's `projects/<project>/` directory, in the Claude config folder, usually `~/.claude` or the account's `CLAUDE_CONFIG_DIR`). `MEMORY.md` there is the index, one line per note with a link; each note is its own markdown file. Also check the user's `CLAUDE.md` and the project's `CLAUDE.md`, but only edit them if the user asks.
- **Codex.** `$CODEX_HOME/memories` (default `~/.codex/memories`). `MEMORY.md` and `memory_summary.md` are the curated files. `raw_memories.md` and `rollout_summaries/` are generated by Codex: read them for evidence, do not edit them.
- **Other harnesses (ACP).** They have no memory location MoPilot knows. Ask the user where their notes live, or whether they mean `AGENTS.md` or another instruction file. Do not invent a location.

If the folder does not exist or is empty, say so and stop.

## 2. Read everything first

List the files with sizes and dates, then read all of them. Do not change anything yet.

## 3. Find the problems

- Duplicates and near-duplicates: same fact in several notes.
- Contradictions: keep the newer or better-evidenced one, and say which you dropped.
- Stale facts: a path, name, version or decision that the repository or system no longer matches. Check cheaply (does the file exist? does the command still work?) before deleting.
- Notes that are really one-off task logs, secrets, or things derivable from the code. These do not belong in memory.
- An index that is long, unordered, or points to missing files.

## 4. Propose, then apply

Show a short plan: files to merge, rewrite, delete, and the new index. Wait for the user's approval. Then:

- Merge into the clearest existing file; keep one topic per file with a clear name.
- Keep each note's key facts and why they matter; drop narration.
- Rewrite the index: one line per note, grouped by topic, each under about 150 characters.
- Never include credentials or tokens. If you find one, tell the user and remove it.
- Keep a copy of what you delete until the user confirms (for example move it into a `.consolidated-<date>/` folder next to the notes).

## 5. Report

Say what changed in a few lines: files merged or removed, facts corrected, and anything you were unsure about and left alone.
