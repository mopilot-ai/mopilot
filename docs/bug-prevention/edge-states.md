# Edge states

One of the [bug classes](README.md#bug-classes). A pull request adds its note about this class as a file of its own in
`notes/edge-states/` (one note per file), not below; the bullets below are the earlier notes.

The first run, an empty list, a missing file, an unborn repository, an index of -1, an already aborted signal
(#151, #155, #356, #380, #488).

## Search for and ask

- Ask: *what if it is empty, missing, -1, or already done?*
- Ask: *is a prefix of streamed input shown as if it were the whole?* A prefix of Markdown is not the Markdown of that prefix.

## Notes

- A basename check alone does not prove a child path: empty names, `.` and `..` pass it. Reject those reserved names before joining imported profile metadata to its root; preserve legitimate custom names, including names that merely start with dots.
- Chat snapshots require a first usable segment and usable entries throughout the list. Reject empty, non-array and malformed persisted segment collections; record a newer-schema write lock before rejecting an unusable future record so a later ensure cannot overwrite it. Legacy readers retain their explicit first-segment fallback.
- `findIndex`/`indexOf` return -1, which `slice`/`splice` read as the last element (`plugin/missing-index`).
- Parent-pointer walks in durable transcripts need a visited-id guard; valid JSON does not prove the chain is acyclic.
- An abort listener added after the signal aborted never fires; check `signal.aborted` first.
- A vendor call sequence can reach the backend before the chat has a tab: Codex's `cua.createBrowserTab('iab', url, { visible })` sets the browser's visibility before it opens the tab. Apply such a request to the tab opened next instead of refusing (`tests/iabBackend.test.ts` replays that sequence in a fresh chat).
- Search limits must count the final ranked, distinct results. Ask whether a candidate cap before ranking
  or deduplication can discard the best match; test a preferred result beyond that candidate cap.
- UI-state migration and restore must validate object-record roots before field checks or object spread: valid JSON can be a primitive or array. Share the JSON-record guard across migration, preference and renderer-state boundaries, preserve invalid saved roots before a live writer replaces them, and test both backup and current-state shapes.

- Browser view lifecycle callbacks must allow a missing guest host: main-owned views are valid without an app window. Popup cleanup and focus recovery check only hosts that exist, and one optional window-lookup helper prevents passing missing contents to Electron. Test native fallback popups, nested close and recovery to the surviving view.

- #800: File-size guards cover every file consumed by an operation, including SQLite WAL, SHM and journal sidecars. A deliberately rejected oversized sidecar must escape optional-file error handling and remove any temporary copy before returning the refusal.
- #806: Bookmark folder bounds distinguish source folders from the generated import root: loading and validating an imported item must preserve the root plus all admitted source folders, so restarting cannot change its deduplication key. Local bookmarks retain their own bound.
- A turn's reply is its last reply, not its last item. A chat's saved notes (an account switch, the answers to a question card) come back after a reload behind the reply of the turn they followed (`withChatNotes`), and `splitTurn` read the last item as the answer, so a reloaded turn folded its own reply into "Worked for". It now skips trailing status notes; `tests/asyncQuestions.test.ts` covers notes before and after the reply, running or done.
- #1500: A turn can have no prompt and no reply: Codex's compaction turn holds only a `contextCompaction` item, and a Claude Code or ACP `/compact` reads back as the command alone. The handoff record rendered these as an empty exchange ("the agent continued on its own" / "no reply"); `shared/handoff.mjs` now writes one line for a turn that only compacted the context. `tests/handoff.test.ts` replays each harness's own history builder.
- A query that may hold spaces also matches what it produced. The `@` list's query runs from `@` to the caret, spaces
  included (`@My chat`), so the `@/path ` a picked file left behind matched again on the next caret move and reopened
  the list on that path; its popover layer then dropped View → Search Files (shortcuts wait while a popover is open),
  which failed main-e2e on b135dda and held merges for three hours (#1496). The composer remembers the mention it
  inserted, and `composerPopup` opens nothing for that `@` while its text is intact. Test the caret moving after an
  inserted result, not only the insertion.
- #1570: A path a tool tells the agent to write into must exist when it is named. `browser_tabs_context` announced the chat's upload folder, which was made only when a screenshot was attached, so an agent's `printf > <folder>/x.txt` failed in a fresh chat and it went looking for another chat's folder. Make the folder before naming it, and name none that could not be made; a test with fake paths (`/up/c1`) checks only the text, so test with real folders that the named path is a directory.

- Active work can replace a finished-state renderer and silently discard its disclosures. Test reasoning expansion while text streams, when a tool starts, with empty/redacted text, and with the preference disabled; stable item keys must preserve opt-in expansion across activity changes.
- A per-item label that is right for one item can be wrong for a run of them: "Thought for Ns" (#1721) was checked on one thinking block, and a Claude Code turn of several short blocks stacked "Thought for 2s" rows, while Claude Desktop shows one row per stretch with the durations summed (ion-dist `Th`). Consecutive thoughts now merge through `mergeThoughts` (stepModel.ts) in every group renderer. When a row matches a reference app, check two and three of the same item back to back, live and read back, and read how the reference groups them.
- #1867: "never" is not "lapsed". A Claude Code CLI login nobody had signed in to was listed as the account in use and shown as "In use · Sign in again", while Codex in the same state showed "Not signed in · Sign in". Account surfaces are tested across signed in, lapsed, unverified, checking, not started and limited (`tests/accountSurfacesConsistency.test.ts`); include "never signed in" for every harness, and check that no surface says "again" or "In use" for an identity that never existed.
- #1870: an action's label must fit the state it sits beside. A signed-in basic harness listed its agent's own first sign-in label ("Login with opencode") next to "Signed in". When a button moves from the signed-out row into a signed-in row's details, name what it does there ("Sign in again").
- Streamed Markdown was revealed a character at a time, so `**bol`, `` `co ``, `[text](ur`, a table header before its delimiter line and a list marker alone rendered as text, then changed form when they closed: React remounted what was on screen and its fade played again, which read as flicker. A reveal now ends only where every construct opened in the paragraph has closed (`src/lib/streamCut.ts`); `tests/streamFlicker.test.ts` streams replies in deltas of several sizes and fails if any element showing text leaves the DOM. Unpaced streaming Markdown (reasoning, a plan) shows only up to the same point (`settledText`).
- #2034: a second surface for the same state must carry its reason and next step. The welcome page's Chrome row showed only main's label ("Not connected") while Settings → Browser showed the same state with its reason and Connect. Render a state's reason and steps from one shared source (`capabilityReasonText`, `runChromeExtensionAction`), and test the new surface with every state main's own producer makes (`tests/welcomeChrome.test.ts`), not a hand-picked few.
- #2119, #2120: the narrowest window is an edge state. In a 1024-wide window (the CI runner's screen) with both side panels open, the chat column is about 440px wide; the Codex gave-up banner kept its three one-line actions beside text allowed to shrink to nothing, so the text went a letter a line, the banner grew to 3,400px and the transcript between it and the down notice had no height: a chat read from disk drew only its pinned last turn, and the chat's Retry sat under the notice. A row of text beside actions that keep one line wraps (`flex-wrap: wrap`, the text `flex: 1 1 16em`), checked through the app stylesheet by `tests/noticeRowWrap.test.ts`; check a UI change in a 1024×682 viewport with the side panels open, not only a wide window.
- A Chat font size other than the default 14px is an edge state. The task list's step markers sat in a fixed 20px box at the top of a row whose text line is `1.5 × --fs-chat`, and seven warning, error and menu rows nudged their icon down by 1-3px tuned for the default size, so every one drifted above its text as the font grew. An icon beside wrapping text in a top-aligned row is one text line tall (`height: 1lh`) and centres its glyph, checked through the app stylesheet by `tests/iconLineCentre.test.ts`; check a UI change at a larger Chat font size, not only the default.
- A folder outside git, or a repository with no commits, is an edge state for every worktree choice. The new-chat bar kept a greyed-out Worktree switch there (and showed it working while the folder was still being read), the `/worktree` entry flipped a setting that did nothing, and a session proposed in its own worktree from such a chat read "In a worktree" and failed at Start, since main can't make one. Ask of every worktree choice what happens where none can be made: read `useWorktreeSupport` (src/lib/branchList.ts, which answers with `worktreeUnsupported`'s reason), offer no choice outside a repo, and keep it off with the reason in a repo with no commits. A start the user asked for (a proposal's Start, "start it" in a later turn, "Always start a new session") falls back to the folder in main (`folderIfNoWorktree`, spawn.cjs), since only main sees every one of those paths, and only on `unsupported` (ChatStarter.newWorktree): a worktree that fails in a repo is still refused, never swapped for the parent's folder; an agent's own start gets the typed error it can act on.
- A recovery card can fit horizontally and still push the composer below the window. Long permission instructions at 24px filled the chat column even though its scroll width passed. Bound the instructions' own scrolling area relative to the viewport and let it share the available height with an expanded multiline draft, keeping Try again beside it; CM-H20 checks the stylesheet's boundary and shrinking budget, and the targeted app check verifies the composer and retry stay in view, the final instruction can be scrolled into view, and recovery preserves the draft. Inspect both axes and reachable actions in the screenshot, not only a width assertion.
- A compact control can inherit a full-width session row's geometry even when its contents look small. For sidebar account controls, check the computed cascade and actual hover footprint, the open-menu state, and separation from the chat list; cover long identity/plan text and larger type without crowding adjacent actions. Rendering the text and testing clicks alone does not verify the hit area.
- A filter that leaves something out says why. Setup's brain step offered only harnesses with an account a brain could run on now, so a signed-in harness at its usage limit vanished without a word while its chip and the account menu said "Limit reached" (#2281). Setup and Settings' role picker now place an account by one rule (`brainAccountUse`, src/components/momo/settings/perUse.ts): offered, listed at its limit with its state until it resets, or left out. Ask of a list built by a filter: *does the user see what was filtered out, and why?*
- A message still being sent is an edge state of the message. A new chat's starting bubble (`StartingChat`) drew every attachment as a name chip, so a pasted image read "Pasted image" until the chat started, while the sent bubble showed the picture. The bubble's parts are drawn by the component the sent message uses (`MessageImages`, pending: pulsing and not zoomable, as Claude Desktop's pending attachments), checked by `tests/messageImagesUI.test.ts`; a placeholder, optimistic or queued copy of something renders through the settled view's components, never a second drawing of them.
- A selection's ends are not where its text ends. A triple click (or a drag to the end of a line) on a reply's last paragraph ends the range at offset 0 of the block after it, the message's action row, so the selection toolbar, which wanted both ends inside one message body, showed neither Add to chat nor Ask in side chat for a whole paragraph. Its tests and the CUJ built the selection with `selectNodeContents`, which never makes that shape. Decide what a selection covers from its text (`messageBodyRange` in src/lib/messageSelection.ts clamps an end that reaches past the body over nothing but whitespace), and test a selection feature with the real gestures (triple click, drag past the line end, Shift+arrows across a block) as well as a programmatic range.
