# External contracts

One of the [bug classes](README.md#bug-classes). A pull request adds its note about this class as a file of its own in
`notes/external-contracts/` (one note per file), not below; the bullets below are the earlier notes.

The code assumed behavior the real CLI, protocol, library or OS does not have: an RPC method that does not
exist (#21), Git run from a subfolder or before the first commit (#488–#491), an option a tool ignores (#388),
a changed protocol shape (#420, #448), a file format an older build cannot read (#102, #135).

## Search for and ask

- Ask: *what shows that the other side behaves this way, in every version we support?*

## Notes

- Read-only app-state readers validate a JSON object before publishing it to startup services; parsing successfully does not exclude null, arrays or scalars. Use the shared record parser, retain unknown fields in valid records, and leave durable backup/recovery to the writer.
- Scheduling watermarks from disk or another app must be valid millisecond timestamps before comparison. Invalid local baselines recover at the current start; an invalid native handled-time marker makes its store unrecognized, so it cannot suppress runs forever or be rewritten as never handled.
- E2E fixtures: enable the fake computer helper when asserting computer-tool exposure. For controlled radio inputs whose value commits after IPC, click and wait for the checked state; synchronous `check()` cannot verify the asynchronous commit. Keep the awaited settings behavior pinned by a focused renderer UT. Permission-guide assertions name the missing permissions and the System Settings action the current health surface offers. Scope repeated settings actions to the intended row's exact title; descriptions and per-harness health rows can repeat another control's name.
- Use the generated protocol types (`src/protocol`) instead of hand-written method names and payloads; check
  a vendor assumption against the real binary or its documentation and say which in the pull request.
- Tool results: normalize a `{content}` wrapper through `toContent` just like a bare list before handing it to MCP/Codex; response text readers use `contentBlocks` for record-shaped entries.
- Stream fragments: use `streamDelta` to validate text and reasoning indices before batching, retry progress or appenders. Live reasoning buffers admit integer indices below the shared 4096-part client resource limit, preventing unbounded padding from an external index. Malformed fragments cannot count as model output; empty strings are valid, and other notification payloads retain their own contracts.
- Message block arrays: use `contentBlocks` (or `contentBlockEntries` when indices form item IDs) for display readers: known text/reasoning fields must be strings, with absent fields normalized to empty; ownership checks must reject non-record blocks and require typed text/metadata markers rather than discard them and claim the line.
- JSONL: decode records before checking their fields; whitespace and escape spelling do not define a record's type. Use `parseJsonRecord` from `shared/jsonRecord.mjs` for object-record boundaries, and `jsonStringField` for bounded, potentially partial prefixes.
- RPC line framing: valid JSON scalars and arrays are not message objects. Guard the object boundary before interceptors, callbacks or pending-request dispatch; client streams drop invalid frames and the authenticated tool socket answers with an invalid-request error, then handles the next valid message. Keep pre-authentication rejection behavior intact.
- Legacy chat conversion: validate segment native ids before converting them, and keep path construction, conversion and count reads inside per-chat failure boundaries. Fallback records must fit canonical filenames; preserve files whose named owner cannot be read or does not match their body, together with their original UI metadata. A damaged chat must not prevent healthy chats from loading, or be overwritten by a fallback record while its original data is unreadable.
- Git: run from the repository root, pass paths after `--` with `:(literal)`, use `-z` output and the parsers in
  `electron/platform/gitParse.cjs`, and handle an unborn `HEAD` (`shared/gitHead.mjs`).
- Codex: collaboration receivers are children only for `spawnAgent` (`isCodexAgentSpawn`); message, wait and close receivers do not establish ancestry. Explicitly loaded roots keep their routing ownership. Approval ancestry also uses that spawn predicate and valid thread IDs, preserves first parents, refuses cycles, and follows the full chain rather than truncating deep nesting.
- CLI wrappers: separate report/output options from test selection before expanding suites or related files; read enforcement results from the same destination passed to the report writer. Exercise the command entrypoint with both a passing and failing custom-directory report.
- A refusal that pauses its own turn must publish its specific reason before the pause cancels the turn; the refusing call keeps that reason while sibling calls are still aborted. Exercise the real stop/interrupt callback when testing unattended refusals.
- Built-in browser pages: a web page is untrusted, and Chromium keeps its storage (IndexedDB, DOM storage) and browser-side work in MoPilot's main process, so a page can grow main until the whole app dies. Do not assume Chromium bounds it (Google Chrome grows the same way); the memory guard (`electron/capabilities/browser/memoryGuard.cjs`) stops the pages' renderers from a worker thread, since the flood starves main's own timers. A new kind of page host (a new partition, window or webContents type) must show up in the pages it watches.
- Next.js (web/): a layout does not render again on client navigation, so a check made only there does not guard
  its pages. Every admin page awaits `requireRole` first (`web/tests/adminGuard.test.ts`); `currentUser` is
  cached per request, so the layout's and the page's checks share one session query.
- macOS privacy: since macOS 27 another app's data folder under `~/Library/Application Support` (Google Chrome's,
  Microsoft Edge's) can be stat'ed but not listed or read without Full Disk Access (EPERM). A probe that turns
  EPERM/EACCES into "not there" hides an installed app: report it as blocked (the browser import's
  `needs_full_disk_access`, as for Safari) and offer Full Disk Access.
- gh in scripts run by hand (release backfills): read GitHub data with `gh api` (the REST shape is GitHub's, the
  same for every gh), not `gh <command> --json <fields>`, whose fields come from the installed gh: gh 2.63.2's
  `gh release view --json assets` has no `digest`, so a SHA-256 check failed with "undefined" after uploading
  (`scripts/github-release.mjs`). A field GitHub itself may leave out (an old asset's `digest` is `null`) fails
  with a message naming it.
- Built-in browser page scripts: Electron's frame events (`did-frame-navigate`, `dom-ready`) come after the document's first scripts may have run, so a main-world wrapper the page must not get ahead of (the passkey watch) goes in through `runBeforePage` (`electron/capabilities/browser/documentScripts.cjs`), a CDP new-document script on the page and each out-of-process frame. Its Page domain must stay on, and every client of the page's debugger runs auto-attach as `AUTO_ATTACH` (`plugin/auto-attach`; pausing new frames hangs out-of-process frames in Electron 44); a client joining later (a tab's turn, the Browser plugin) takes the already attached frames from `framesOf`, since CDP reports them only once, and the plugin cannot turn the Page domain or those scripts off. Acting on every frame (the passkey Cancel) asks them all at once, so one frame that doesn't answer holds up no other.
- Electron's `console-message` names the main frame for a same-process subframe's message (Electron 44, seen in the benchmark VM): a report from page code must name its own document, and an action on it must reach every frame (`browser/passkeys.cjs`, CM-B27).
- A posted input event is delivered after the call that posted it returns: the window server hands it on later. Lifting a global shortcut only for the duration of the post let the agent's own Escape reach the re-registered Esc-to-stop hotkey and end its own turn. Keep such a guard in place until the event has been delivered (`ControlIndicator.suspendEscape`'s settle, CM-Q15).
- A page in a background tab of the user's Chrome is hidden: Chrome draws it no frames, so CDP input to it hangs (a mouse move waits about five seconds for its answer), does nothing on the first click, and is never routed into a cross-site iframe. A host whose pages live in Chrome's window (`inputWhileHidden`) emulates focus on attach (`Emulation.setFocusEmulationEnabled`, as the Codex Browser plugin does) and never waits for a pane to lay its pages out (CM-Z22, CM-Z23). Check this before driving any page that is not in front.

- An OS encryption availability probe does not guarantee the subsequent encryption succeeds. Boolean-returning secret stores use `encryptForStore` to turn either failure into a failed save before writing; keep the saved bytes intact and allow retries. Throwing transaction APIs retain their explicit failure boundary. Never pass secret-bearing OS exception text to a credential tool result or log.
- A successful token HTTP status does not establish usable credentials. Validate nonblank string refresh/access tokens before persisting or publishing either authorization-code or refresh replies; a first sign-in also requires its gateway key. Share token-pair validation and lifetime fallback between both grants so a malformed success cannot replace a working account or force immediate refresh through a NaN expiry.
- A successful file stat does not establish that the following read stream will open or finish. Local update serving uses `pipeline` rather than a bare `pipe`: it handles source errors after headers or partial bytes, terminates the response, and destroys the file read when the client disconnects. Test both sides of the transfer, including failures between metadata lookup and reading.

- Dictation engines normalize replies before crossing IPC: accept record-shaped text results, preserve empty/no-speech answers, and reject non-string transcripts and error-shaped answers without text. HTTP failures choose only nonblank string messages from known fields, then fall back to status; arbitrary backend objects must never reach text insertion or toast rendering.
- Chrome stops an idle MV3 service worker (about 30 s, or when its DevTools target closes) and starts it again on the next event: MoPilot's extension's WebSocket drop is not the extension letting go of a chat. It keeps the chats' sessions in `chrome.storage.session` and reports their tabs again on the next `session.open`, so main closes those chat links `resumable` (`chromeExtension.cjs` `#dropPorts`) and the Chrome host keeps their tabs with the debuggers let go (`ChromeTabContents.suspend`/`resume`); only a connection MoPilot closed, or the Playwright Extension's, takes its tabs with it. State the worker keeps in memory is gone after the restart: persist it, or let go of what it held (the stopped worker's debuggers) when the new one starts (CM-Z29).

- Parsed recording JSON is not a recording contract: require a record, string transcript and valid numeric date before publishing it to Settings. Project only those display fields and derive clip identity from its filename, never from stored metadata. Strip only the terminal metadata extension through one helper shared by listing and paired-audio retention. Validate transcript input before creating files so the writer cannot produce entries the reader must discard.

- Claude authentication status requires an explicit boolean loggedIn and string-or-null optional identity/billing fields. Share one parser between CLI detection and account refresh: malformed success output is a failed read that preserves the saved account, while a valid false remains a real sign-out. Allow missing optional fields and future extra fields without coercing malformed values into authentication state.
- node:assert does not format a failing value cheaply: it calls util.inspect at depth 1000 with `customInspect: false` (so `util.inspect.custom` is ignored), appends a diff even when a message is given, and util.inspect stops only at cycles on the current path, so one `assert.equal(element, null)` on a happy-dom node reached tens of gigabytes within seconds; `--test-timeout` and `--max-old-space-size` do not stop synchronous work or memory outside the heap. Every unit-test entry point loads `tests/support/brief-assert.ts`, which reports DOM nodes, DOM/React events and React fibers as one-line summaries (node:assert, node:assert/strict and `t.assert`), and `tests/support/rss-watchdog.ts`, a worker thread that kills a test process above `UNIT_TEST_RSS_LIMIT_MB` (6 GB by default) and names its file. A new test entry point loads both (`tests/rssWatchdog.test.ts`).
- Live CLI usage fixtures must derive reset dates from the query clock, including the year at calendar boundaries. Exercise the actual fake query through the production parser and reset policy; fixed-date parser examples are not proof that a live fixture stays active. Migration specs should invoke the feature UI rather than assume a renderer/CDP key event activates a native application-menu accelerator.
- Squirrel.Mac installs an update only when it satisfies the running app's designated requirement, not merely when both share a team: an Apple Development build's requirement pins that leaf certificate's name, so every Developer ID release failed with "code failed to satisfy specified code requirement(s)" after a full download. Gate auto-update on the bundle's leaf certificate being Developer ID Application (`developerIdTeamOf` in electron/updates/updater.cjs reads `codesign -dvv`), and check a signing gate against the real signatures of a release and a dev build, not just the presence of a team id.

- CSS `height` does not hold what the box contains: it pins the border box, and a line box larger than it overflows (a flex/grid item centred in it spills above and below its own background). A box whose type reads the Chat font-size setting therefore cannot keep a pinned pixel height that only fits at 14px; it takes `min-height`, or a leading that fits the box where the box's shape is the design (a round marker, a square key). Two more traps: under `border-box` the pinned height also has to hold the vertical padding and borders, and a `min-height` on a shared rule clamps a *narrower* rule's smaller `height` upwards whatever its specificity, so both rules have to say `min-height`. `tests/styles.test.ts` measures every rule in every stylesheet the app loads at each size the Chat row offers.
- A basic (ACP) harness that opens a session is not proven able to run a turn, and a config patch MoPilot passes a harness replaces whole rows. dsh's patch set its `acp` row to `{ model }` and so dropped its provider: under MoPilot every dsh turn failed with "has no provider/model", key or not, while admission read Ready, because dsh lists no auth methods and opens sessions without a key (#1201). Patch only the rows a quirk owns, with every field it needs (`dsh.patch.yml` is pinned to its two privacy rows by a test). When a harness can be ready without a sign-in, declare what it needs in its quirks `setup` (`model: true` when its session must offer a model, `ready(ctx)` to find a key where the harness looks, `error` for its first-turn words, `reason` for how to set it up): admission and both chat stages (session/new, session/prompt) then read Signed out through one helper (`setupFailure`, `hasModel` in electron/harness/acp/signin.cjs). Check a new harness, and any patch it is given, in the VM through `initialize`, `session/new` and one `session/prompt`, with and without its credential, not only through admission.
- The Claude Code CLI keys an added login's macOS keychain item by a hash of the literal `CLAUDE_CONFIG_DIR` string and does not resolve links (CLI 2.1.302), so the string, not the folder, identifies the login. Never re-derive it from today's userData: each account record keeps the path it signed in with (`configDir`, `electron/identity/contract/accountDirs.cjs`), a moved folder is reached through a link at that path, and a path that can't be kept reads "Needs to be confirmed again" rather than a bare Signed out. A recorded path is accepted only as that account's own `claude-accounts/<id>` folder (`accountConfigDir`), since removal deletes it.

- Native configuration folders: before trusting or handing one to a harness, enumerate the sources each
  admitted family/version actually selects, including defaults, alternate manifests, merge/replace rules
  and parse fallbacks. A normalized display manifest is not that inventory. Add inert paired-source
  fixtures through the production reader, approval and delivery gate, including raw values that parse
  differently across runtimes (such as integer versus floating JSON tokens). Assert per-family selection,
  disclosure and approval identity: an unaccounted selected source must not cross the native boundary,
  while an ignored malformed source must not reject a valid override on another family.
- A CI runner is not the machine it emulates. #1457 smoke-launched the x64 macOS app under Rosetta on GitHub's arm64
  macOS runners, assuming a translated Electron app starts as on an Intel Mac; there it printed nothing for 120 s, and
  release 0.3.33 failed while the arm64 app started in 4 s. Start each build on hardware of its own architecture
  (`mac-x64-verify` runs on `macos-15-intel`), and `tests/releaseSuitesMatch.test.ts` refuses a translated start.
- Background computer use assumed every cmd combination in an app is a menu-bar shortcut and every pop-up needs
  the app in front, so inside a macOS Save panel it refused the Where pop-up and cmd+shift+g/d and sent the model
  to `desktop_app_menu`, which has no command for a panel's folder; the 12-grid bench's agents got stuck saving
  (#1381, #1528). A refusal names a way out that works where the refusal happens: the background refusals come
  from one factory each in `appScopedUtil.cjs` (`menuControlRefusal`, `contextMenuRefusal`, `keyVerdict`) carrying
  `PANEL_HINT`, file panels have `desktop_app_file_panel`, and CM-D14 checks the factories and the helper's own
  refusal. Two more assumptions fell in the VM: the panel (macOS's open-and-save panel service) takes no keys and no
  Go to Folder while its app is inactive, so a folder outside the sidebar needs the brief-foreground rung; and on
  macOS 26 a Save sheet wider than its document window is a window of its own with no accessibility window, so its
  Save button had no element index until `SheetPool` matched the sheet to it. Check an OS assumption against the
  real UI in the benchmark VM, not only the menu bar.
- A fake of a library call settles when the real one does, as its documentation says, not at once. Electron's `navigationHistory.restore()` writes the history immediately but resolves only when the page finishes loading (and rejects on a Stop), so #1435's fake that resolved at once let a Duplicate wait for the page and roll back a slow one (#1362). Copy history through `restoreHistory` (`plugin/history-restore`), and test an operation with the external promise pending, rejected late and settled late.
- When a feature default changes the tools or servers announced to a harness, reconcile every exact inventory assertion, including release-only E2E specs, in the same change. Check default, disabled/unshipped and native-controller ownership modes through the real visibility and channel grouping with an inert provider boundary; a unit fixture that registers only the old tool sets does not establish the default app inventory (#1497, #1544).
- Chromium input into a page no shown window displays: a built-in browser view parked in its never-shown window (views.cjs) reports itself visible and paints, but Chromium keeps its widget hidden, so a mouse or key event over CDP hangs about five seconds and lands nowhere, or the first one after the view wakes is dropped (#1509: the first click on a POST form's submit button did nothing in a background dev instance and a computer access chat). The user's Chrome does the same to a background tab (CM-Z22), and that fix was not carried to the in-app browser's parked views, whose test even asserted they never emulate focus. Every CDP input sender goes through `focusForInput` (views.cjs) via the tab or `PanelBrowser.send` (`plugin/raw-input`), and the browser host kit's fake debugger drops input to an unshown view without emulated focus (`FakeDebugger.dropped`), so a test that sends input to a parked view sees what Chromium does.
- CDP's `Page.navigate` answers a link that serves a file (Content-Disposition: attachment) with `errorText: net::ERR_ABORTED`, and the session's `will-download` can arrive just after that answer. #1484 taught the pane's load-failure handlers about downloads but not the agent's navigate, which told the agent "Couldn't open" for a file that was downloading (#1523). Every reader of a navigate's `errorText` asks `becameDownload` (electron/capabilities/browser/downloadNavigations.cjs); CM-K31 in tests/controlMatrixDownloadNav.test.ts scans electron/ for one that doesn't.
- JSON-line pipes deliver arbitrary fragments, not complete or small records. A growing-buffer newline search can consume quadratic CPU on main; use the shared linear framer, offload growing records, and verify bounded queueing, EOF/stop order, generation retirement and composer/scroll/chat-switch latency. The `json-line-rescan` lint guard and fragmented-record scan-count test enforce the mechanical case.
- When a presentation change extends or replaces an accessible name (a running row that now names the program instead of "Running a command"), reconcile every release-only locator that names it, including negative assertions; select it in E2E through a shared matcher in `tests/e2e/fixtures/` that a unit test checks against the rendered label. Preserve exact command and outcome identity; accept only the optional presentation fields emitted by the real formatter. A shared matcher must be checked against the rendered component label as well as malformed, wrong-command and wrong-outcome counterexamples, so unit tests catch the drift before E2E (#1557, #1572, #1614).
- A GUI app does not get the user's shell environment. Opened from the Dock or Finder, MoPilot's own PATH is launchd's (`/usr/bin:/bin:/usr/sbin:/sbin`), so `gh` in `/opt/homebrew/bin` was never found by the app's own calls (PR status, the PR monitor, `gh:run`), while agent shells, which get the login shell's env, ran it fine (#1580). Every command main runs by name gets `shellEnv.childEnv()` (electron/platform/env.cjs) or goes through `run` in electron/app/commands.cjs; `plugin/login-env` flags a user-installed CLI spawned without an env. Test it with `process.env.PATH` set to launchd's.
- Sharing a CLI's config folder by linking its entries shares whatever is there when the link is made (#1582). `ClaudeAccounts.prepare` linked `~/.claude/.oauth_refresh.lock`, its `.owner` record and `.storage-write.lock` into an added login's folder because the CLI happened to hold them; the CLI takes those locks with mkdir in its own config folder, so the login waited on another login's lock or, once the link dangled, never got it, and its token expired. Per-login entries, transient ones included, are excluded by name (`isLockEntry`), and links an older version made are removed. Also: after a 429 with nothing cached, `/usage` prints only its local breakdown; main counts an answer without figures as a refusal and backs off.
- The Claude Code CLI checks a tool path's resolved form against its own config folder's unresolved one (CLI 2.1.306), so a linked entry in an added login's folder loses the CLI's own allowances there: with `plans` linked to `~/.claude/plans`, writing the session's plan file in plan mode asked for an Edit card (#1933). `plans` is each login's own folder (`OWN_FOLDERS`, `ownFolders`); auto memory under the shared `projects` link has the same gap (#2010). Before linking a new entry, check whether the CLI allows anything in it without asking.
- Cryptographic negative fixtures must keep local public/private keypairs coherent and forge only the peer's wire claim. A provider may reject a mismatched JWK before the proof under test, even if another runtime imports it. Assert the intended authentication failure separately from malformed-key rejection; for an attacker proof helper, include a genuine-key positive control and a wrong-private-key negative control over the same public transcript. The computer-access handshake fixture enforces coherent private-key imports so permissive runtimes cannot hide this mistake.
- A connection's initial snapshot can contain events received before consumers install listeners. Reconcile that snapshot through the same ownership-checked path as live events, and test child-before-parent replay, duplicate reports, removed parents and retired links. A popup's optional opener field is not proof that every browser popup supplies it; never infer ownership from timing, focus or URL. Native grouping continuations must still belong to the exact session and child after each lookup before changing groups or publishing ownership.
- Chrome's `tab.openerTabId` is the tab strip's opener, which Chrome sets to the window's *active* tab when a link opens a new tab, not the page that opened it. An agent's Chrome tab is a hidden one, so a `target=_blank` link it clicked named the user's tab and the new tab never joined the chat (#1642, found only in the VM: the extension's fake set `openerTabId` to the chat's tab). A popup is the chat's by `webNavigation.onCreatedNavigationTarget`'s `sourceTabId`, the page Chrome says opened it; the shipped worker (`background.mjs`, `sourcedPopups`) adopts nothing by `openerTabId`, which `tests/support/extension-background/worker.ts` checks. Read an extension API field's documented meaning before a fake gives it the value a test needs. The first VM check of that fix looked like the bug again because `Extensions.loadUnpacked` on a profile that had loaded the extension before keeps that load's service worker: the new manifest with the old worker scripts, whatever the version says. The bench loader (`bench/lib/chromePipe.mjs` `loadExtension`) now uninstalls the earlier load first; when a real-app check of an extension change shows the old behaviour, check the source the worker runs (`Debugger.getScriptSource` on its target) before the code.

- A pre-commit guard reads what Git will commit from the index, never from working-tree existence. A test can stage a fixture and remove its working copy while the blob remains staged; a staged deletion can also have a recreated working copy. Exercise real cached A/M/T/R/D states, rename destinations with detection on and off, and NUL-delimited unusual paths. The #1507 guard missed this because its fake defined `exists=false` as deletion; `tests/precommitFixtures.test.ts` now checks the authoritative index independently of cleanup.
- A dependency's claimed retry or recovery is checked in its source or driven by a test before the caller relies on it. @electron/notarize wraps its staple in promise-retry but never calls the retry callback, so it tries once; #1414 assumed it retried and releases 0.3.39 and 0.3.42 failed on that staple. Release scripts run every `stapler` command through scripts/notary.mjs (tests/notaryInvariant.test.ts). Size a retry for an outside service from the longest failure observed, not one try's worth: 0.3.39's DMG staple failed 5 tries over 2.5 minutes, so the ticket service now gets 8 tries backing off to 5 minutes (about 22 minutes), and no extra calls to it (`stapler staple` already validates).

- A harness we start can write to files that belong to the user, and can lose its children without telling us. Probe both with the real binary in a throwaway home before relying on an assumption: Codex's app-server writes a trust entry into `~/.codex/config.toml` for every writable thread in an unknown folder unless the thread's own config carries one (#1346), and a harness SIGKILLed outside MoPilot re-parents its commands to launchd, out of reach of any walk from it; macOS hides the environment of Apple's own binaries, so `ps -E` cannot tag them (#1486). Record what the harness starts while it runs, and name the platform gap you leave.
- #1619: A control's name alone does not say what it does. "Allow", "Accept" and "Continue" grant a third-party app access to the account only on a consent page, so siteRisk's name list (deletes, purchases, messages) never asked for them and an agent's click granted access in every mode. Judge a user's decision by the page it is on as well as the button (`browser/consent.cjs`), and for each new kind of step that is the user's to decide, list it in `VERBS` so CM-J07 makes you say whether Full access covers it.
- A Chrome `tabs.onUpdated` group change is one ownership transition; a second event is not guaranteed. Retire the source membership and reconcile the destination from the same validated native report. Native tab ID plus chat is not an operation identity: after A → B → A, old create replies, queued closes and debugger cleanup must still name the retired membership. The authenticated `tab-membership-v1` capability negotiates opaque receipts before session replay, without changing protocol version 1; manual user-group proof remains separate from popup opener lineage and raw Tab properties. Capture receipt and attachment link before asynchronous work, fence create publication at decode and after await, and recheck admission after synchronous retirement callbacks. Serialize receipt-bearing storage snapshots, and rotate restored receipts on every worker incarnation: uncertain durability must cancel old queued closes/releases rather than restore their authority. Ordinary network reconnect keeps receipts. Only an extant suspended wrapper with a previous negotiated receipt anchors a fresh same-chat wrapper after worker restore; closed or closing tabs and legacy/unknown IDs never authorize admission. Explicit close intent suppresses persisted manual replay across reconnects until a new live manual transition. CDP events require the acknowledged current attachment and membership, plus receipt validation at main; tab ownership alone cannot relabel retired native events. The `controlMatrixChromeMembership*` and `controlMatrixChromeGroupTransfers` tests exercise these boundaries without Chrome or sockets. When socket-dependent cases cannot run locally, reuse their exact report scenario through the real frame parser and decoder without a socket; do not replace it with a parallel expectation. Wait for an ordered completion marker, then assert malformed events were ignored alongside valid legacy receipt-less and negotiated current-receipt controls.
- Another app's folder is that app's to clean up. Version 2 of the prefs kept older profiles' worktrees in `$CODEX_HOME/worktrees`, and the Codex app's startup cleanup force-removed them there, uncommitted changes and all, under chats still working in them. Main refuses to make or restore a worktree in the Codex app's folder (`inCodexWorktrees` in electron/platform/git.cjs), and version 3 moves such profiles to `~/.mopilot/worktrees`. Before MoPilot writes into a folder another app manages, check whether that app deletes what it finds there.

- Scripted external CLIs are producers of the same contract as their real service. Pass their actual process output to the production reader in focused UT; hand-built parser fixtures alone miss stale CLI responses when required identity fields change. Keep module-relative URL dependencies in related-test selection so changing the executable fixture selects that contract test.
- A paginated commit list is a page of the reachable graph, not complete first-parent branch history. Bound lookbacks by the branch commits they mean, continue from immutable parent SHAs, and keep failed or malformed continuations distinct from exhaustion. Combined commit statuses are paginated too: follow their count, reject incomplete or changing pages and test a required context beyond page one. Fixtures need real parent links, qualifying results beyond page one, successful side-branch noise and a moving branch head; empty parent objects cannot establish traversal correctness.
- When matching a reference interaction, check its actual component, styles and state-specific actions rather than inferring them from general design tokens. A downloaded update offers a restart; a manual installer offers a download. Keep version and retry detail accessible, and verify the compact, busy and failure states in the real host: component tests alone cannot establish visual parity.
- #1777: Electron's `outlivesOpener` also applies to a popup a `createWindow` handler shows as a tab: left `false`, Electron destroys that tab when the tab it came from closes, which Chrome never does. When a page moves from one kind of surface to another (a popup window to a pane tab), list the lifetime rules the old surface carried and decide each again for the new one; probe the framework with a bare Electron script when its docs only describe the old surface.
