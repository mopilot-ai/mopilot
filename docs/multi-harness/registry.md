# ACP registry agents

Settings → Other agents → Agent directory adds agents through the public [ACP registry](https://agentclientprotocol.com/registry). Browsing and refreshing fetch metadata only. Choosing Install, Update or Repair explicitly prepares the selected pinned package or checksummed binary. A native integration and a registry distribution keep separate MoPilot harness identities, even when they use the same vendor.

The generic ACP adapter supplies chat, approvals, sessions and MoPilot tools. Registry agents must pass the existing protocol, native-session recovery and tool-connection admission checks before the picker offers them. Installing an agent does not assert compatibility: it can still need sign-in or appear unsupported, with the reason on its harness row. Features vary with the capabilities the agent declares. Existing native integrations and their release defaults are preserved.

On macOS and Linux, registry installs can use a target-specific binary with a published SHA-256, npm/npx, or uv/uvx. Install Node.js/npm or uv first when the distribution needs that manager. Binaries without checksums are not downloaded. Archives cannot extract paths, links or special files outside their managed folder. Windows registry installation is unavailable; its existing native integrations continue to follow their current policy.

Main owns the metadata cache, installer and installed records under `registry-agents` in the app data directory. Windows send only an agent id; they cannot supply executable metadata. Reads coalesce, installs serialize across agents, and repeat clicks join the current install. Package output and Stop use the existing shared harness-install jobs. Installation continues when Settings closes. A failed refresh retains the last valid catalog; a failed install preserves the preceding version and remains retryable.

Each installation receives its own directory. Updates change the launcher used for new sessions while retaining the executable a running session already uses. The installed manifest restores the managed harnesses before admission and chat recovery at app startup. Terminal sign-in uses a separate launcher so the authentication method's arguments and environment replace the ACP defaults. Managed agent paths are shown in Settings but cannot be replaced by an external CLI path; restore missing files with Repair in the registry.

Managed npm and uv distributions also keep a private cache per installed version under `registry-agents/.packages`. Preparation, chat and terminal sign-in share that stable path. Failed or cancelled preparation removes its unpublished cache after process retirement; updates retain earlier versions' caches for existing sessions. This avoids reusing an interrupted shared npx installation. Cache selection uses the managers' documented [npm](https://docs.npmjs.com/cli/v11/commands/npm-exec/) and [uv](https://docs.astral.sh/uv/concepts/cache/#cache-directory) options.

Registry metadata lives in `shared/acpRegistry.mjs`; installation, persistence and catalog refresh live in `electron/harness/registry`. The installed contracts join the same shared harness catalog in main and the renderer. Harness-specific protocol behavior stays in adapters, and registry agents use the same chat identity, cancellation and tool authorization services as other ACP harnesses.
