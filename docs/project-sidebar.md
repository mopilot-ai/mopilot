# Project navigation

The Projects sidebar lists the projects and folders you are working in, as Claude Code's sidebar does: a project or folder appears while it has an active chat, and archiving its last active chat removes it. Project placement and chat activity are separate choices.

- **Project order → Recent activity** is the default. Projects with the newest active chat appear first. Recent activity can move a project when its newest active chat is archived.
- **Project order → Custom / Name** are explicit alternatives. Custom saves project order and discovered folder placement across restarts, using the existing `sidebarProjectOrder` preference. Newly added projects start at the top; existing projects stay in place as chats change.
- Drag a project or discovered folder before another to set its position. Dragging switches to Custom and preserves the order of other groups, including projects the sidebar does not list now. Pinned projects stay above unpinned projects, and existing sidebar sections still determine group membership.
- **Chat order → Last updated / Manual order** controls only chats within a project. Existing chat-sort preferences remain in effect.
- **Recents** lists active chats across projects by their recorded activity by default, while retaining support for direct dragging into manual chat order. Opening a recent chat unfolds its project and reveals the selected chat without changing project order.
- Each chat list starts with 5 chats in a project or Recents, and 20 in the one-list view or Pinned; a fold never hides a single chat. "Show N more" reveals 5 at a time; "Show less" appears once every chat is shown and folds back. The owning list (its project, the one-list view, or Recents for a chat with no project) stretches past that default to reach every open session, running session, background task, and session waiting for input. An open or active nested session keeps its family head in that list too. Order stays unchanged; once work finishes or a pane closes, the automatic extension can shrink, while manually revealed rows stay revealed. Show less is disabled when folding to those sessions would hide nothing. Pinned and Recents do not stretch for a chat its project already shows. Explicit project and nested-session collapse choices remain in effect.

## Projects without active chats

A saved project or discovered folder with no active chat leaves the sidebar, as a folder whose sessions are all archived leaves Claude Code's. It keeps its name, section and Custom position, and returns there when a chat starts in it (the starting chat shows at once) or one of its chats is restored. A saved project stays on the Projects page and in the new chat's project menu. Archived chats remain under **Archived chats** (the sidebar's MoPilot menu, or Settings). The Projects list offers **Add a project folder** only while no project is saved.

Projects are listed from the chats MoPilot has loaded. A project whose chats all lie further back in a long history appears once **Show more chats** loads them, as Claude Code's **Load more sessions** does.

Three cases keep an empty project in the sidebar:

- **Pinned**: a pinned project or folder stays, with **New chat** and **View archived chats** actions. Pins follow the folder when saved aliases are combined or a discovered folder becomes a saved project; either Unpin control clears all equivalent pins. To pin one that is not listed, pick it for a new chat and pin its row.
- **Home page**: on the home page, the project or folder its new chat goes to is listed and is the sidebar's current row. That is the one picked for the chat (from the Projects page, the new chat's project menu, a project's own **New chat**, or **Add new project**), else the project of the newest chat, else the first saved project, the same one the page names. So with saved projects and no chats, the home page's project shows in the sidebar. A chat outside any project (the top **New chat**) has no row, and **New chat** is the current one; so it is whenever no row stands for the home page: a machine picked with no folder yet, or the one-list and activity views, which draw no project rows. Picking another project moves the row; leaving the home page drops a project that has no chat, and sending the first chat keeps it, through the starting chat, on the chat's page. Local folder selections follow the canonical folder even when its path is an alias or it becomes a saved project.
- **Launch**: until the chat lists have answered (or a saved snapshot says what the projects hold) and MoPilot knows which machine each ACP chat runs on, every project stays listed, so a project with chats never flashes out of the list. Before the lists answer, a project with no chat yet says **Loading…**.

Archiving a chat shows its title and an **Undo** action for eight seconds. Undo waits for any worktree cleanup before restoring the chat. Restoring a chat uses the harness's recorded activity timestamps rather than promoting it as new activity. **Remove from sidebar** is a separate project action; chats remain in history and local files are retained.

## Unavailable folders

A local project or folder whose displayed path is confirmed missing, unreadable, untraversable, or no longer a directory is hidden from the sidebar, including pinned and home-target rows. Chats remain in Recents, search and archived history; an open chat remains selected and reachable in Recents. Saved projects, folder names, pins, sections, ordering and worktree recovery metadata are retained.

The sidebar checks its local folders on mount, every minute while the window is visible, and when the window shows or regains focus. Hidden folders remain candidates and return in their saved position once accessible, subject to the active-chat/pinned/home rules above. Unknown, timed-out or transient filesystem reads keep the last confirmed state; a new folder remains visible while its first check is pending. Paths on other machines are never checked on this Mac. Checking availability does not restore or delete a worktree: sending an existing chat still uses the shared managed-worktree recovery guard.

## Remote projects

SSH sessions show a terminal icon in the sidebar and session title bar. Cloud machines show a cloud, other remote machines show a monitor, and this Mac’s background Host shows a laptop. A remote project puts its location icons and expand or collapse chevron after its name. When all sessions in a project share one Host, including folded sessions, the heading shows their icon once. Mixed projects and standalone lists identify the machine on each session. Hover the icon for the machine name. The sidebar adds a machine or parent folder hint when folder labels would otherwise look alike. The full working directory is available from the session’s **Copy** menu. When a session needs attention, its row shows the status below the title.

Remote Host worktrees are grouped under their original repository and machine. Each chat still runs in its own worktree; the group's **New chat** action selects the original repository on that machine. Existing worktree names, pins and manual chat orders follow the combined group, with an explicit repository name or chat order taking precedence. A saved worktree collapse carries over until the repository group is explicitly expanded or collapsed. A hidden worktree stays hidden without hiding visible siblings; hiding the repository hides all its worktrees. Grouping recognizes the Host's `<repo>.worktrees/<escaped-branch>` folder convention without reading remote paths on this Mac.

Profiles without a project-sort preference start in Recent activity order. Explicit Custom and Name choices are retained, along with existing chat order, pins, sections, and collapse state. Project and chat sorting remain independent.

## A project across machines and Cloud

The desktop Projects sidebar groups local and machine chats and Codex Cloud tasks together when their repository identifies the same project. A repository group without a local project uses the repository name and owner. The heading marks the locations of its sessions, including folded sessions. A heading with more than two remote location types uses one icon with a tooltip listing them. Machine chat rows identify where they run. Codex Cloud rows open the task and its diff. A task needs an environment with one known repository before it can join a project. Tasks without that information stay in Cloud. If an environment changes repositories while tasks are loaded, its earlier tasks also move to Cloud.

Two separately saved local projects keep their own rows. Verified remote sessions that could belong to either share a repository row. A machine folder with an unknown repository still has its own folder row. A temporary loss of connection retains the last verified repository for that machine and folder.

The project’s New chat button opens the composer with its local checkout selected when available. Choose a known machine folder or Codex Cloud environment from **Work in**. With a remote-only project, a sole available destination is selected. The composer asks before sending when a choice is needed. A restored repository draft asks for a location again. MoPilot checks the project and account before starting a Codex Cloud task, and the machine registration and checkout before starting a machine chat. Opening an existing session routes to the location already holding that session.
